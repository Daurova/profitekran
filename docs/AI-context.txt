# 📦 Контекст проекта: «ВДОХНОВЕНИЕ» (TV PWA)

## 🏗️ 1. Общая Архитектура («Цитадель»)
*   **Подход:** Модульный монолит (основной продукт) + независимые сервисы-«форпосты» (Docmost).
*   **Монорепозиторий:** Все проекты лежат в корневой папке `content`.
    *   `apps/tv-pwa` — клиент для ТВ-приставки.
    *   `apps/admin` — админка (Next.js + shadcn/ui) — *в разработке*.
    *   `apps/landing` — лендинг — *в разработке*.
    *   `services/api` — бэкенд (Node.js + Fastify) — *текущий этап*.
    *   `docmost` — локальная вики (Docker, порт 8000).

## 💻 2. Стек технологий
*   **Фронтенд (PWA):** React 19 + Vite, TypeScript, FSD (Feature-Sliced Design).
*   **UI:** Mantine (dark theme, Glassmorphism).
*   **Навигация:** `@noriginmedia/norigin-spatial-navigation` (управление пультом).
*   **PWA:** `vite-plugin-pwa` (автообновление, иконки).
*   **Бэкенд:** Fastify, TypeScript, Zod (валидация).
*   **База данных:** PostgreSQL + Prisma (в планах).
*   **Линтер:** Oxlint.

## 📺 3. Особенности ТВ-плеера
*   **Железо:** Приставка Tanix (Android TV).
*   **Багфикс:** Чтобы видео не зависало на 6-м ролике (лимит декодеров Chrome), используется **один тег `<video>`** с жесткой очисткой памяти (`removeAttribute('src')`).
*   **Кнопка Play:** Чтобы скрыть системную кнопку Play браузера между роликами, используется «Занавес» (черный оверлей), который закрывается за 0.8 сек до конца видео и открывается, когда новое видео реально начало играть.
*   **Оптимизация:** Видео перекодированы в 720p (H.264) через HandBrake, чтобы приставка не тормозила.
*   **Автозапуск:** Установлен `Auto Web Launcher` на приставке. Он открывает URL ноутбука (`http://192.168.77.123:4173`) при включении ТВ.
*   **Оверлей:** Стильный виджет с часами и логотипом «ВДОХНОВЕНИЕ» (шрифт Raleway, матовое стекло).

## 📋 4. ТЗ от PR-отдела (Умный эфир)
*   **Цикл 8 минут:** 444 сек BASE (атмосфера) + 36 сек PROMO (3 ролика).
*   **Реклама:** 6 сек кофе-якорь + 15 сек промо + 15 сек промо (с QR-кодами).
*   **Умный планировщик:** Сервер должен сам собирать плейлист по правилам (Dayparting — утро/вечер, Частотные капы — кофе 2 раза в час, мастера 1 раз в 2 часа).
*   **Offline-First:** Из-за нестабильного интернета телевизор должен скачивать расписание и видео на **месяц вперед** и работать автономно из кэша.

## 🎯 5. Текущий статус и следующий шаг
*   **Сделано:** Работающий PWA-плеер, красивый UI, автозапуск, решение проблем с зависанием.
*   **В процессе:** Создание бэкенда на Fastify в папке `services/api`.
*   **Следующий шаг:** Настроить TypeScript (`tsconfig.json`), структуру папок по Clean Architecture (domain, application, infrastructure) и написать первый роут для отдачи плейлиста.

## 📺 3. Текущие проблемы и решения
*   **Кэширование видео:** **Проблема.** Service Worker (Cache API) не может сохранять видео из-за конфликта с `Range Requests` (статус 206). 
*   **Решение (Big Tech Way):** Переход на **IndexedDB**. 
    *   Вместо попыток сохранить видео через Cache API, мы будем скачивать видео целиком через `fetch`, сохранять как `Blob` в IndexedDB, а затем отдавать плееру через `URL.createObjectURL()`.
*   **Остальное работает:** Сайт открывается, плейлист приходит с API, видео играет, HTTPS и домен настроены.

## ⏭️ 4. Следующий шаг
Переписать логику кэширования на фронтенде с Service Worker (Cache API) на **IndexedDB**.

*   `GET /playlist`: Генерирует плейлист (планировщик).
*   `POST /upload`: Принимает файл, читает длительность через `music-metadata`, загружает в S3.
*   `POST /add-video`: Сохраняет метаданные в базу (с длительностью и типом).
*   `GET /videos`: Отдает список всех видео из базы.
*   `DELETE /videos/:id`: Удаляет видео из базы и S3.
*   **CORS:** Разрешены методы `GET`, `HEAD`, `POST`, `PUT`, `DELETE`, `OPTIONS`.

## 🗄️ 4. СХЕМА БАЗЫ ДАННЫХ (Prisma)
*   **Модель `Content` (Видео):** `id`, `tenantId` (пока `default`), `type` (enum: BASE, PROMO, COFFEE_ANCHOR, COFFEE_OFFER, SERVICES, MASTER, PRODUCT, PARTNER), `url` (ключ S3), `durationSec`, `hasAudio`, `maxPerHour`, `cooldownMin`, `requiresConsent`, `dayparts` (массив строк), `createdAt`.
*   **Миграции:** 
    1. `20261102135601_init` (создание Content).
    2. `20261102183637_add_dayparts` (добавление dayparts).
    3. `20261104120000_add_tenant_id` (добавление tenantId).
*   **Планы на будущее:** Добавление таблиц `Tenant`, `User`, `Screen` (с массивом `contentIds` для связи экрана и видео).

## ⏭️ 5. СЛЕДУЮЩИЙ ШАГ (В РАЗРАБОТКЕ)
Переход к **полноценной SaaS-платформе (Мультитенантность)**.
1.  **Схема БД:** Создать таблицы `Tenant` (клиент), `User` (сотрудник), `Screen` (экран). Использовать массив `contentIds` в `Screen`.
2.  **Авторизация:** Вход в Админку по **номеру телефона (SMS OTP)**. Регистрация на SMS.RU, получение `api_id`. Эндпоинты `/auth/send-code` и `/auth/verify-code`. JWT-токен с `tenantId`.
3.  **Device Provisioning (Привязка экранов):** Приставка генерирует `deviceId`. Клиент в Админке вводит код активации. Сервер связывает экран с тенантом.
4.  **Биллинг:** Проверка `subscriptionEnd` у тенанта (если не оплачено — не отдавать плейлист).

**Готовые архитектурные паттерны:** Clean Architecture (Domain, Application, Infrastructure), FSD (Feature-Sliced Design) для фронтенда, React Query для стейт-менеджмента на клиенте.

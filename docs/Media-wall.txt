# 📦 КОНТЕКСТ ФИЧИ: «МЕДИАСТЕНА» (Video Wall)

## 🏗️ 1. Физическая конфигурация (Железо)
*   **3 телевизора** (39–45 дюймов), стоят **друг над другом** (вертикальная стена).
*   Ориентация экранов: **горизонтальная** (стандартная 16:9).
*   **Размеры стены:** Ширина ~100 см (1920 пикс), Высота ~168 см (3240 пикс — по 1080 на каждый ТВ).
*   **Приставки:** 3 отдельные приставки (например, X88 PRO X5M), подключенные к каждому ТВ.
*   **Сеть:** Мобильный роутер (интернет может пропадать на 8+ часов).

## 🎬 2. Контент (Видео)
*   **Формат:** Вертикальный контент (9:16, как Reels/Shorts). Стоковых видео 1920x3240 не существует.
*   **Источники:** Pexels, Pixabay (фильтр «Vertical»), съемка на телефон вертикально.
*   **Распределение:** 
    *   Верхний ТВ — верхняя треть видео.
    *   Средний ТВ — центральная треть.
    *   Нижний ТВ — нижняя треть.
    *   *(Клиент загружает одно вертикальное видео, система сама режет его для экранов).*

## 🖥️ 3. UI/UX в Админке (Big Tech Way)
*   **Никаких вкладок.** Основной экран Админки остается чистым (как сейчас).
*   **Кнопка «Медиастена»:** В шапке админки (рядом с названием компании) появляется кнопка **«Медиастена (Video Wall)»**.
*   **Модальное окно (или страница `/wall`):** По клику открывается «Мастер настройки стены».
    *   Выбор раскладки (3 вертикально, 2 горизонтально и т.д.).
    *   Поля для ввода кодов приставок (Верхняя, Средняя, Нижняя).
    *   Кнопка «Собрать стену».
*   **Монетизация (в будущем):** Кнопка «Медиастена» бесплатна. Платной можно сделать «Загрузку видео» (лимит на количество или объем), чтобы стимулировать переход на тариф Pro.

## 🏗️ 4. Архитектура синхронизации (Master-Slave)
*   **Проблема:** BroadcastChannel не работает между устройствами. Запуск с пульта дает рассинхрон.
*   **Решение:** **WebSocket-сервер** на бэкенде (Fastify + `@fastify/websocket`).
*   **Логика:** 
    *   **Master (Ведущий):** Отправляет текущее время видео (`currentTime`) каждые 500 мс через WebSocket.
    *   **Slave (Ведомые):** Слушают канал и подстраивают `video.currentTime`.
    *   **Fallback (при потере связи):** Ведомые не встают на паузу, а продолжают играть по своему таймеру. При восстановлении связи — синхронизируются.

## 🚨 5. Graceful Degradation (Аварийный режим)
Если интернет пропадает надолго (8+ часов):
*   **Верхний ТВ:** Показывает только **Часы** (HTML-оверлей, работает от системных часов приставки).
*   **Средний ТВ:** Показывает **Видео** (из кэша IndexedDB).
*   **Нижний ТВ:** Показывает только **Логотип** (SVG из кэша).
*   *Часы не зависают*, так как используют системное время Android TV.

## 🗄️ 6. Изменения в Базе Данных (Prisma)
*   Добавить модель **`VideoWall`**: `id`, `name`, `layoutType` (3_vertical, 3_horizontal, 2_vertical, 2_horizontal), `tenantId`.
*   Добавить в **`Screen`**: `wallId` (связь со стеной), `wallPosition` (1 = верх/лево, 2 = центр, 3 = низ/право).

## 🗄️ 7. Изменения в API
*   `GET /playlist?deviceId=...`: Если экран привязан к стене, отдавать плейлист с учетом `wallPosition` и `layoutType`.
*   **WebSocket `/sync`**: Канал для синхронизации времени между приставками.

## 🖥️ 8. Изменения на Фронтенде (PWA)

# 📦 КОНТЕКСТ ФИЧИ: «МЕДИАСТЕНА» (Video Wall & Asymmetric Screens)

## 🏗️ 1. Архитектура и Сценарии
*   **Классическая видеостена (1 видео на 3 экрана):** Отложена. Требует огромных разрешений и сложной синхронизации.
*   **Асимметричная видеостена (Приоритет):** 3 экрана, каждый выполняет свою роль. Это решает проблему рассинхрона и экономит ресурсы приставок.

## 🖥️ 2. Роли экранов (Асимметричный режим)
Клиент в админке назначает роли для каждого из 3 экранов:
1.  **`INFO` (Верхний экран):** Показывает часы, логотип и размытый фон (атмосферу). Не зависит от видео.
2.  **`VIDEO` (Средний экран):** Показывает основной видеопоток (рекламу мастера, услуги).
3.  **`TICKER` (Нижний экран):** Показывает QR-код или бегущую строку. **Жестко связан с тем, что играет на среднем экране.**

## 🎬 3. Контент и Связь (QR + Video)
*   В базе данных у видео (`Content`) появляется поле `actionUrl` (ссылка для записи).
*   Если играет видео «Мастер маникюра», на нижнем экране появляется QR-код на запись к этому мастеру.
*   Если играет «Атмосфера» (без `actionUrl`), нижний экран показывает общий QR-код («Записаться в кофейню»).

## 🕒 4. Синхронизация (Time-based Sync) — Вариант для теста
*   **Без постоянного WebSocket.**
*   Сервер отдает расписание с абсолютными временными метками (`startTime`, `endTime` в UNIX).
*   Экраны `VIDEO` и `TICKER` играют по своим системным часам.
*   **При обрыве интернета (8+ часов):** Оба экрана продолжают работать по локальному кэшу (IndexedDB) и системным часам. Рассинхрон в 1-2 секунды считается **допустимым**.
*   **Безопасность (Data Mismatch):** Если нижний экран понимает, что его часы сильно отстали/убежали, он **скрывает QR-код** и показывает заглушку («Загрузка...»), чтобы клиент не отсканировал неверный код.

## 🚨 5. Graceful Degradation (Аварийный режим)
*   **Верхний экран:** Часы продолжают идти (системное время Android TV).
*   **Средний экран:** Видео играет из кэша.
*   **Нижний экран:** Показывает последний QR-код из расписания (или заглушку).

## 🗄️ 6. Изменения в Базе Данных (Prisma)
*   Добавить модель **`VideoWall`**: `id`, `name`, `tenantId`.
*   Добавить в **`Screen`**: `wallId` (связь со стеной), `wallRole` (Enum: INFO, VIDEO, TICKER).
*   Добавить в **`Content`**: `actionUrl` (строка, необязательное).

## 🖥️ 7. UI в Админке (Big Tech Way)
*   Основной экран Админки остается чистым.
*   **Кнопка «Медиастена»:** В шапке админки. По клику открывается модальное окно (или страница).
*   **Мастер настройки:** 
    1. Клиент вводит 3 кода приставок.
    2. Назначает им роли (Верхний = Инфо, Средний = Видео, Нижний = QR).
    3. Система создает `VideoWall` и привязывает экраны.
*   **При загрузке видео:** Клиент может добавить `actionUrl` (ссылка для QR-кода).

## ⏭️ 8. План внедрения (Пошагово)
1.  **БД:** Миграция (модель `VideoWall`, поля в `Screen` и `Content`).
2.  **Бэкенд:** Роут создания стены и отдачи расписания с временными метками.
3.  **Админка:** Кнопка «Медиастена» и модальное окно с ролями.
4.  **Плеер:** Логика ролей (`INFO` — часы, `VIDEO` — плеер, `TICKER` — QR-код).
5.  **Тест:** Загрузка видео с `actionUrl`, проверка работы QR-кода на нижнем экране.

# 📦 КОНТЕКСТ ФИЧИ: «ГИБРИДНАЯ МЕДИАСТЕНА» (Info + 2x Video)

## 🏗️ 1. Физическая конфигурация и Концепция
*   **3 телевизора** (39–45 дюймов), стоят **друг над другом** (вертикальная стена).
*   Ориентация экранов: **горизонтальная** (стандартная 16:9).
*   **Ключевая идея:** Мы не растягиваем одно огромное видео на 3 экрана. Мы используем гибридный подход:
    *   **Верхний экран (INFO):** Часы, логотип, QR-код.
    *   **Средний и Нижний экраны (VIDEO):** Одно видео, растянутое на две высоты (без нарезки на 3 части).

## 🎬 2. Контент и Связь (QR + Video)
*   В базе данных у видео (`Content`) появляется поле `actionUrl` (ссылка для записи).
*   Когда на нижних экранах играет видео «Мастер маникюра», на верхнем экране появляется QR-код на запись к этому мастеру.
*   Если играет «Атмосфера» (без `actionUrl`), верхний экран показывает общий QR-код («Записаться в кофейню»).
*   **Связь жесткая:** QR-код наверху должен соответствовать видео внизу секунда в секунду.

## 🕒 3. Синхронизация (Master-Slave через WebSocket)
*   **Средний и Нижний экраны** должны быть синхронизированы **идеально** (чтобы картинка на стыке не рвалась).
*   **Нижний экран** назначается **Master (Ведущий)**. Он отправляет текущее время видео (`currentTime`) каждые 500 мс через WebSocket.

*   **Верхний экран (INFO)** не участвует в синхронизации видео. Он просто слушает WebSocket-канал и меняет QR-код, когда Master объявляет: «Начал играть видео №5».

## 🚨 4. Graceful Degradation (Аварийный режим при обрыве связи 8+ часов)
Если интернет пропадает и нижние экраны рассинхронизируются:
1. **Средний экран (Slave):** Перестает слушать Master'а и показывает видео **целиком** (в обычном формате 16:9, как на одном телевизоре).
2. **Нижний экран (Master):** Переходит в режим заглушки. Показывает логотип, часы и текст: *«Пожалуйста, подождите»*.
3. **Верхний экран (INFO):** Показывает заглушку *«Запись на услуги — обратитесь на ресепшн»* (скрывает QR-код, чтобы не было путаницы).
4. **Как только связь вернется:** Все три экрана автоматически перестраиваются обратно в режим видеостены (видео снова растягивается на два экрана, QR-код появляется наверху).
*   **Часы** на верхнем экране продолжают идти (системное время Android TV).

# 📦 КОНТЕКСТ ФИЧИ: «ГИБРИДНАЯ МЕДИАСТЕНА» (Video Wall)

    4.  **3 Вертикально (`3_v`):** Экран 1 (Видео верх) | Экран 2 (Видео низ) | Экран 3 (Инфо + QR) — *Инфо внизу*.

## 🗄️ 3. База данных (Prisma)
Файлы в **`content/services/api/prisma/`**:
*   **`schema.prisma`:**
    *   **`VideoWall`:** `id`, `name`, `layoutType` (3_v, 2_h и т.д.), `tenantId`.

        *   *Логика:* Если тип BASE, то `qrUrl` может быть общим (или подтягиваться из общих настроек). Если тип PROMO, то `qrUrl` уникален для этого ролика.

## 🏗️ 4. Бэкенд (API)
Файлы в **`content/services/api/src/`**:
*   **Роуты:**
    *   **`infrastructure/http/wall.route.ts`** (новый файл):
        *   `POST /walls` — создание стены (принимает `layoutType`, массив экранов с кодами и ролями). Сохраняет в `VideoWall` и обновляет `Screen` (проставляет `wallId` и `wallRole`).

# 📦 КОНТЕКСТ ФИЧИ: «ГИБРИДНАЯ МЕДИАСТЕНА» (Video Wall)

## 🏗️ 1. Физическая конфигурация и Схемы
*   **Телевизоры:** 2 или 3 шт. (39–45 дюймов), горизонтальные.
*   **Схемы (выбор в UI):**
    1.  **2 Горизонтально (`2_h`):** Экран 1 (Видео полное) | Экран 2 (Инфо + QR).
    2.  **2 Вертикально (`2_v`):** Экран 1 (Видео полное) | Экран 2 (Инфо + QR) — *Инфо внизу*.
    3.  **3 Горизонтально (`3_h`):** Экран 1 (Видео лево) | Экран 2 (Видео право) | Экран 3 (Инфо + QR).
    4.  **3 Вертикально (`3_v`):** Экран 1 (Видео верх) | Экран 2 (Видео низ) | Экран 3 (Инфо + QR) — *Инфо внизу*.

## 🖥️ 2. UI в Админке (FSD, Big Tech Way)
Все файлы находятся в **`content/apps/admin/src/`**. Компоненты разделены по принципу Single Responsibility.

*   **Страница:** `screens/video-wall/ui/VideoWallPage.tsx` — тонкая обертка, собирает виджеты. Роут `/wall`.
*   **Виджет превью:** `widgets/video-wall-preview/ui/VideoWallPreview.tsx` — интерактивная схема. Клик по экрану открывает инлайн-ввод кода (без модалок). Содержит словарь `LAYOUT_ROLES` (где инфо-экран для вертикальных схем стоит внизу).
*   **Фича формы (Сборщик):** `features/video-wall/ui/VideoWallForm.tsx` — собирает компоненты вместе, управляет общим стейтом (`codes`, `baseVideos`, `infoData`, `promoVideos`).
*   **Фича «Основной эфир»:** `features/video-wall/ui/BaseWallContent.tsx` — отвечает только за загрузку базовых видео (список, время) и настройку Инфо-экрана (общий QR и текст).
*   **Фича «Реклама»:** `features/video-wall/ui/PromoWallContent.tsx` — отвечает за загрузку рекламных роликов (индивидуальный QR и текст для каждого).
